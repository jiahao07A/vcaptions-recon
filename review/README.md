# 审查规范

本目录记录对 vCaptions 逆向重建工程的分层审查结果。审查采用多 subagent 并行方式，每层由一个 subagent 负责，结果独立落盘以便追溯。

## 工程背景（供审查者快速进入状态）

这是一个从 Chrome 扩展产物（vCaptions 2.4.6）逆向重建的可维护工程。核心事实：

- 原始产物已归档在 `assets/baseline/extension-v2.4.6/`（28 文件，18.24 MB）
- 10 个 Parcel bundle 被拆成 240 个模块，放在 `src/bundles/`
- 构建（`tools/build.mjs`）从拆分模块重组 bundle，当前 10/10 与基线字节一致
- `src/readable/` 是格式化后的可读视图（派生，勿改）
- `src/overlay/` 是可编辑源码（`adopt` 生成，构建优先使用）

## 审查原则

1. **以证据为准。** 每个结论必须附可复现的验证方式（命令、行号、输出片段）。禁止"看起来没问题"这类判断。
2. **区分严重级别。** 见下表。不要把风格问题混进正确性问题。
3. **区分"事实"与"推断"。** 若结论依赖假设，明确写出假设。
4. **不修改代码。** 审查者只写报告，修复由后续环节统一处理。
5. **不重复已知问题。** 先读 `review/known-issues.md`，已在册的不要重复报告，除非发现新的证据或更严重的影响面。

## 严重级别定义

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| **P0** | 会丢失用户工作或产出错误产物，且不易察觉 | 编辑被静默覆盖；构建出的包无法加载 |
| **P1** | 功能缺陷或误导性结论，但有明显症状 | 校验器漏检；文档数字与实际不符 |
| **P2** | 健壮性/可维护性问题 | 缺边界处理；错误信息不明确 |
| **P3** | 风格与整洁度 | 命名、注释、重复代码 |

## 报告格式

每个 subagent 在指定文件里按以下结构写报告：

```markdown
# <层名> 审查报告

审查者：<subagent 标识>
审查范围：<文件/目录清单>
审查时间：<ISO 时间>

## 结论摘要

一句话说明这层是否健康，以及最严重的问题是什么。

## 发现

### [P0/P1/P2/P3] <问题标题>

- **位置**：`path:line`
- **现象**：观察到什么
- **证据**：复现命令 + 输出
- **影响**：会导致什么后果
- **建议**：怎么修（不要求实施）
- **置信度**：确定 / 较高 / 存疑（说明依据）

## 已确认无问题的部分

列出实际验证过、确认正常的点，便于后续审查不重复劳动。

## 未覆盖的范围

明确说明因时间/权限/依赖原因没查的部分。
```

## 分层

| 层 | 范围 | 关注点 |
| --- | --- | --- |
| L1 构建与字节完整性 | `tools/parcel-split.mjs`、`reconstruct.mjs`、`build.mjs`、`overlay.mjs` | 拆分/重组是否真的无损；边界条件；失败模式 |
| L2 测试有效性 | `tests/*.mjs` | 测试是否真能捕获回归；是否有假阳性/假阴性；覆盖率盲区 |
| L3 文档与事实一致性 | `README.md`、`docs/*` | 文档声称的每个数字/行为是否可验证；工作流指引是否安全 |
| L4 产物可运行性 | `dist/`、`release/`、`tools/check.mjs`、`package.mjs`、`browser-verify.mjs` | 包能否真实加载运行；打包是否完整；清理是否彻底 |
| L5 工具健壮性 | 全部 `tools/*.mjs` 的边界处理 | 异常输入、并发、路径处理、跨平台 |
